## 一、Demo 概述

本 Demo 通过柱状图动态展示多种经典排序算法的执行过程，让学习者直观理解冒泡排序、选择排序、插入排序、快速排序等算法的核心思想与效率差异。用户可以调节数组规模、动画速度、初始数据分布等参数，观察不同算法在各种场景下的比较与交换操作。通过实时的比较次数、交换次数统计和算法时间复杂度标注，帮助学习者建立算法效率的感性认识。

## 二、内容要求

### 知识点覆盖
- 冒泡排序（Bubble Sort）的原理与实现：相邻元素两两比较交换，每轮将最大元素"冒泡"到末尾
- 选择排序（Selection Sort）的原理与实现：每轮选择最小元素放到已排序序列末尾
- 插入排序（Insertion Sort）的原理与实现：将元素逐个插入到已排序序列的正确位置
- 快速排序（Quick Sort）的原理与实现：分治思想，选取基准值分区递归排序
- 算法时间复杂度概念：最好、最坏、平均时间复杂度的含义
- 算法稳定性概念：相等元素相对位置是否改变
- 数据初始分布对排序效率的影响：有序、逆序、随机、几乎有序

### 目标用户
- 计算机专业大一/大二学生，正在学习数据结构与算法课程
- 对编程感兴趣的高中生，初次接触算法概念
- 信息技术课教师，用于课堂演示排序过程

## 三、呈现框架

### 交互工具型
- 参数控制：
  - 数组规模（n）：范围 10-100，步长 1，默认值 30
  - 动画速度：范围 0.5x-5x，步长 0.5x，默认值 1x（对应每步约 50ms）
  - 初始数据分布：下拉选择，选项包括【随机 / 近乎有序 / 逆序 / 几乎有序 / 少数重复】，默认随机
  - 排序算法选择：下拉选择，选项包括【冒泡排序 / 选择排序 / 插入排序 / 快速排序 / 归并排序 / 希尔排序】，默认冒泡排序
  - 柱体颜色方案：下拉选择，选项包括【高度渐变 / 比较高亮 / 分区着色】，默认高度渐变
- 实时反馈：
  - 柱状图高度对应数组元素值，颜色标识当前操作状态（比较中/交换中/已排序/基准元素）
  - 顶部状态栏实时显示：当前比较次数、交换次数、已完成轮数
  - 右侧信息面板显示：当前算法名称、时间复杂度（最好/最坏/平均）、空间复杂度、稳定性
  - 数组变化时柱体有平滑过渡动画，交换时有高亮闪烁效果
- 预设模式：
  - 预设1：小规模演示（n=10，慢速，冒泡排序）——适合初学者逐帧观察
  - 预设2：效率对比（n=50，快速，算法可切换）——快速对比不同算法
  - 预设3：最坏情况（n=40，逆序数据）——观察最坏时间复杂度表现
- 播放/暂停：
  - 支持播放/暂停/单步前进/重置四种控制
  - 播放时按钮变为暂停图标，暂停时显示播放图标
  - 单步模式下每次点击执行一次比较或交换操作

## 五、技术实现

### 推荐技术栈
- 纯 Canvas 2D 绘制柱状图，性能好，动画流畅
- JavaScript 实现各排序算法的生成器（Generator）版本，便于分步执行和暂停控制
- 原生 CSS 打造精致滑块和按钮样式
- 无需额外框架，轻量高效

### 性能要求
- 首屏加载时间：< 500ms
- 是否需要加载动画：否，内容轻量可直接渲染
- 动画帧率：60fps，柱体移动使用 requestAnimationFrame 平滑过渡

### 响应式
- 移动端适配要求：控制面板在小屏上可折叠或变为底部抽屉
- 柱体宽度自适应画布宽度，保证在任何屏幕尺寸下都能完整显示
- 触控设备支持手指滑动调节滑块

## 七、设计与实现流程

请按照以下流程工作：
1. 理解知识点和教学目标
   - 核心目标：让学习者通过视觉化过程理解排序算法的工作原理
   - 重点：不同算法的比较/交换模式差异、时间复杂度的直观感受
   - 误区避免：不要只追求动画炫酷而忽略算法逻辑的准确性
2. 确定最佳呈现方式（是否符合对应框架的规范）
   - 采用上下分栏结构：上80%画布区展示柱状图，下20%控制面板
   - 左侧参数滑块组：数组规模、动画速度
   - 右侧功能按钮组：播放/暂停/单步/重置 + 算法选择下拉 + 预设按钮
3. 设计视觉方案（配色、布局、动效）
   - 柱体采用圆角矩形，底部对齐，高度按比例映射
   - 比较中的柱体变为橙色并有轻微发光效果
   - 交换时有红色闪烁并伴随位置平滑移动
   - 已完成排序的柱体渐变为绿色
   - 控制面板用 --surface-muted #f3efe9 暖灰色背景
4. 自我审查：有没有落入模板化默认设计？够不够震撼？
   - 检查：是否只是简单的柱状图加按钮？有没有设计感？
   - 优化点：加入刻度线背景、状态指示灯、实时数据波形图
   - 增加算法信息卡片，像精密仪器的读数面板
5. 开始编码实现
   - 先实现数据模型和排序算法的生成器函数
   - 再实现 Canvas 渲染层
   - 最后实现控制面板和交互逻辑
6. 自我审查：交互是否流畅？视觉是否精致？哪里可以再优化？
   - 测试不同速度档位下的流畅度
   - 检查滑块拖拽时的数值实时更新
   - 确认所有预设模式一键切换正常
   - 移动端横竖屏切换测试
7. 保存到指定路径
