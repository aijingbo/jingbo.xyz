## 四、生成要求

### 格式要求
1. **严格按照模板格式**：参考 `00-Demo生成规范与模板.md` 中的模板
2. **编号不能错**：严格按照上表的编号
3. **文件名格式**：`D{编号}-{英文短名}.md`
   - 英文短名用小写字母，单词之间用连字符
   - 例如：`D004-solar-system.md`
4. **保存路径**：
   - 沉浸式 → `/Users/a1/Desktop/jingbo.xyz/docs/03-Demo生成/沉浸式全屏型/`
   - 杂志讲解 → `/Users/a1/Desktop/jingbo.xyz/docs/03-Demo生成/杂志讲解型/`
   - 交互工具 → `/Users/a1/Desktop/jingbo.xyz/docs/03-Demo生成/交互工具型/`
   - 时空叙事 → `/Users/a1/Desktop/jingbo.xyz/docs/03-Demo生成/时空叙事型/`

### 内容要求
1. **每个文档都是完整的、可执行的**——前端拿到就能直接开发
2. **知识点要准确**——不能有科学错误
3. **视觉要求要具体**——不要笼统地说"要好看"，要说清楚配色、气质、参考方向
4. **技术建议要合理**——根据难度推荐合适的技术栈
5. **Skill 关联要有想象力**——思考用户会怎么用自然语言描述这个需求

### 质量标准
- 每个文档不少于 80 行（内容充实，不是凑字数）
- 视觉设计要求部分要有具体的颜色参考和风格描述
- 交互设计要具体到有哪些按钮、哪些参数
- 要体现出"杂志感"和"教育性"的平衡

## 五、工作流程

1. 先读完三份参考文档，理解规范
2. 浏览 50 个 Demo 清单，规划好每个的框架类型
3. 按编号顺序生成，一个一个写
4. 写完一个保存一个，确保不会丢
5. 全部写完后，做一次全面检查：
   - 编号是否连续正确
   - 文件是否都在正确的文件夹里
   - 格式是否统一
   - 内容质量是否达标
